# Note on `loader/upload_ahah.ipynb`, 31 October 2026

Two defects found and fixed in the sibling project uprn-epc are present here. Neither has
shown itself in a run of this notebook, but the conditions are the same. Record of the EPC
case: `uprn-epc/docs/sql/NOTEBOOK_PROBE_2026-10-30.md`.

## 1. A pooled connection can carry an open transaction into a later step

What the notebook does: cells 2, 8, 12 and 14 call `pyodbc.connect(CONN, ...)` with the
default `autocommit=False`; cell 6 does so explicitly; cell 10 connects with `autocommit=True`.
`pyodbc.pooling` is left at its default, `True`.

Why that matters: with the SQL Server ODBC driver, `autocommit=False` means
`SET IMPLICIT_TRANSACTIONS ON`, so a plain SELECT opens a transaction that stays open until a
commit. pyodbc's pool can hand a later `connect` the same underlying session with that
transaction still open, and `autocommit=True` on the new connection object does not close it.
In the EPC notebook, two `CREATE INDEX` statements ran inside the first cell's uncommitted
transaction, held schema locks, and the next cell waited on them without a timeout. The
notebook looked hung.

Fix, four lines, the same as in `uprn-epc/loader/make_notebook.py`:

1. `pyodbc.pooling = False` before the first `connect`.
2. `autocommit=True` on every connection that only reads (cells 2, 8, 12, 14).
3. Keep `autocommit=False` only around the DROP and CREATE of cell 6, commit, then set
   `cn.autocommit = True` before any further query on that connection.
4. `SET LOCK_TIMEOUT 120000` at the start of the cells that write or build indexes, so an
   unexpected lock becomes an error instead of a silent wait.

Test it the way EPC does: run the notebook's own cells in a kernel against a SQL Server
container (`uprn-epc/loader/notebook_probe.sh` is the model), not by parsing the notebook.

## 2. `BULK INSERT` without `CODEPAGE = '65001'`

`docs/sql/import_csv.sql` (generated by `ahah_ingest/sql_check.py`) has no `CODEPAGE`
clause. Without it SQL Server reads the file in the server's OEM code page whatever the
staging collation says. In the EPC probe a non-breaking space (bytes C2 A0) arrived as two
other characters and the digest check failed on every year. If the AHAH CSV holds only ASCII
the load is unaffected, and a loaded table that has passed its digest check is right; the clause
costs nothing and protects the next release. Add `CODEPAGE = '65001'` to the `WITH (...)` of
the generated `BULK INSERT`. SQL Server on Linux does not support it; there, convert the file to
UTF-16LE with a byte order mark and use `DATAFILETYPE = 'widechar'`, as
`uprn-epc/loader/sqlserver_probe.sh` does.

## Decision needed

Whether to apply both now or at the next release of the table. Both change only the loader
and the generated import script, not the data or its digest.

# Beyond the notebook: what else uprn-epc did that this project has not

Checked against this repository on 31 October 2026. None of these changes the data or its
digest; they are build plumbing, probes and documentation. The first three each hide a failure
today.

## 3. The build writes into `results/` directly

`ahah_ingest/pipeline.py: build` makes `results/`, writes the Parquet (line 79), then the
manifest (line 112). A rebuild that stops between the two leaves a new Parquet beside the old
manifest, which no longer describes it, and nothing says so.

uprn-epc builds into `results/.staging_<stamp>/` and promotes the four outputs as one
generation only after every check has passed; the previous files are moved aside first and
moved back if any rename fails, so `results/` always holds a complete, accepted build
(`uprn-epc/epc_ingest/pipeline.py: build, promote`, with a rollback test in
`tests/test_build.py`). Forty lines to copy.

## 4. No probe runs the notebook's own cells

`loader/sqlserver_probe.sh` exercises the import scripts with sqlcmd. Nothing runs
`upload_ahah.ipynb`'s cells in a Jupyter kernel against a server, and that is the only test that
finds a defect like item 1: the hang depends on which pooled session a cell is handed, which
parsing cannot see. uprn-epc's `loader/notebook_probe.sh` builds a client container (Python,
pandas, pyodbc, ODBC Driver 18, nbclient), generates the notebook from a small fixture release
so its embedded hash and digest belong to the fixture, and runs the cells under eleven
scenarios: a clean run, a rerun, a changed byte, four kinds of tampering with the loaded table,
a batch the server rejects, a bad decimal, and reads every loaded cell back to compare with the
CSV. Reuse `loader/notebook_probe/Dockerfile` and `harness.py`; the fixture and the scenario
list are the AHAH-specific part.

## 5. The probe runner can fail silently

`loader/sqlserver_probe.sh` runs under `set -eu` without `pipefail`, and the result captures
end in `| sed | grep -v '^$' > file` (lines 45 and 61), the first with `|| true`. Under `set -e`
a pipeline's status is its last command's, so a failing `sqlcmd` exits the runner with 0 and an
empty or partial file is diffed as if it were a result. The EPC follow-up review found the same
class in its notebook probe. Fix: `set -o pipefail`; capture each sqlcmd's exit status before
filtering; and have the runner re-read the results it is about to trust and fail unless they
hold what it expects (`uprn-epc/loader/notebook_probe.sh`, `tests/test_notebook_probe_exit.py`,
which drives the runner with a fake `docker` on PATH and asserts the exit status).

## 6. The provenance site's checks have no applicability, coverage or condition

`ahah_ingest/provenance_site.py: CHECKS` is a list of (regex, sentence), as in postcode-simd.
It says what a check tests, not which columns it guards, how much of the data it sees, or
whether it runs only under a flag. uprn-epc moved this to `epc_ingest/check_catalogue.yaml`:
per family, the name pattern, what it tests, `applies_to` (a group, a type class or a column
list), `coverage` (for example "three rows per annual file, not every row") and `condition`
(`--verify-archive` or null). The lineage attaches a check to a column only if the catalogue
says it applies, a test fails when a real check is attached to the wrong column, and the
synthetic build is run with and without the flag to show every emitted name matches the
catalogue and every unconditional family is emitted. The manifest of one build is an example,
not the definition.

## 7. Decisions cannot revise one another

`ahah_ingest/decisions.yaml` entries have `date`, `id`, `decision` and `why` only. When a
later decision changes part of an earlier one, the site lists both as reasons and a reader
cannot tell which governs. postcode-simd has `status` and `superseded_in_part`; uprn-epc has
`status` (in_force or superseded), `amends: <id>` and `keeps:` (what of the earlier entry
still stands), and the column page shows the policy in force before the history, with the
"still stands" sentence. Also add a one-line test that the file parses: the EPC file did not,
and nothing had read it until the site generator did.

## 8. Smaller

- `SET LOCK_TIMEOUT` in every notebook cell that writes or builds an index (item 1).
- Shell-runner tests that put the test interpreter's `bin` directory on PATH after any fake
  executable, so the runner's `python3` is the one running pytest (found by the EPC round-3
  review when pytest ran under Miniforge and the runner picked up Homebrew Python).
- Any script that reads a downloaded file (a publisher's PDF, a lookup) runs with the script
  directory off `sys.path` (`python3 -P`) from a directory that does not hold the download.
- Column descriptions quoted from the publisher's documentation carry an attribution kind
  (publisher or project), the page and the pinned file's hash, and a review record in
  `docs/reviews/`; a field the documentation omits is described by the project and says so.
